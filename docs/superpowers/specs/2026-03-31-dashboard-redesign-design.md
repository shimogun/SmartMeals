# SmartMeals ダッシュボードリデザイン設計書

## 概要

SmartMealsのホーム画面をダッシュボード化し、記録タブを統合して2タブ構成に簡略化する。
糖尿病患者（年配ユーザー多め）が1日1回の利用で、記録から献立確認まで最小操作で完結できる設計。

### 対象issue

- #2 食後血糖値と献立の紐付け記録
- #6 お気に入り・定番献立機能
- #8 1日の栄養バランスサマリー
- 追加: オンボーディング、食材の好み/苦手登録、献立生成フロー簡略化

### 設計方針

- ユーザー操作工数を最小化する
- 画面遷移を増やさない（モーダルで完結）
- 現在の3タブ → 2タブ＋設定（ヘッダーギアアイコン）に簡略化
- 記録タブを廃止しホームに統合

---

## 1. タブ構成

```
[今日]  ──  [献立]  ──  ⚙️(ヘッダー右)
```

- **今日タブ:** ダッシュボード（健康記録＋今日の献立・栄養）
- **献立タブ:** 献立生成・保存済み履歴・お気に入り
- **設定(⚙️):** プロフィール編集・食材の好み/苦手・アプリ設定

---

## 2. ホーム画面（今日タブ）

上下セパレート構成。上半分＝健康情報、下半分＝献立系。

### レイアウト（上から順に）

1. **挨拶/日付/名前**
   - 「おはようございます」（時間帯で変化）
   - 日付表示、ユーザー名

2. **血糖値セクション**
   - 入力フィールド: 値(mg/dL) + 食事タイミング(朝/昼/夜) + 保存ボタン
   - 直近の記録値を表示
   - 常時表示（最もよく記録する項目のため）

3. **体重・血圧セクション**
   - アコーディオン（折りたたみ式）で初期状態は閉じている
   - 体重: 値(kg) + 保存
   - 血圧: 収縮期/拡張期(mmHg) + 保存
   - 毎日は計らない人が多いため折りたたみ

4. **今日の献立カード**
   - 朝/昼/夜の3カードを横並び表示
   - 各カードに料理名、カロリー、★(お気に入り)ボタン
   - カードタップ → モーダルでレシピ詳細表示（画面遷移なし）

5. **今日の栄養バランス (#8)**
   - プログレスバー4本: カロリー、糖質、タンパク質、脂質
   - 目標値に対する現在値を表示
   - 色分け: 緑(<80%)、オレンジ(80-100%)、赤(>100%)

6. **明日の献立を更新**
   - 直近の血糖値傾向に基づくメッセージ表示
   - [更新する] ボタン1つで献立再生成
   - 血糖値データは自動取得（入力不要）

---

## 3. 献立タブ

### レイアウト

1. **保存済み献立一覧**
   - カード形式、新しい順
   - 各カードに期間、人数、生成時の血糖値(#2)を表示
   - タップで詳細展開

2. **お気に入り一覧 (#6)**
   - 横スクロールで★登録済みの料理を表示
   - 各カードに料理名、カロリー

3. **[＋ 新しい献立を作る] ボタン**

### 献立生成フロー（1ステップ化）

現在の3ステップウィザード → モーダル1画面に簡略化。

入力項目:
- 期間（3〜7日、デフォルト3日）
- 人数（1〜4人、デフォルト1人）
- 開始日（デフォルト明日）
- 制限レベル（ゆるめ/ふつう/きびしめ、デフォルトふつう）

以下は自動取得（ユーザー入力不要）:
- 血糖値・HbA1c → ホームの記録データから
- 年齢・性別・活動レベル → プロフィールから
- 食材 → 設定の好み/苦手から

### お気に入り機能 (#6)

- 献立の各料理カードに★ボタン
- タップでお気に入り登録/解除
- お気に入りの料理は次回の献立生成時に優先的に組み込まれる
- AsyncStorageに `favorite_meals` キーで保存

### 血糖値紐付け (#2)

- 献立保存時に直近の血糖値を自動取得して紐付け
- 保存済み献立カードに「生成時: 130 mg/dL」と表示
- 紐付けデータは SavedMealPlan の `glucoseAtGeneration` フィールドに格納

## 4. 設定画面

既存の設定画面に「食材の好み」セクションを追加。

### 食材の好みセクション（新規）

- 好きな食材: タグ形式で表示 + [+]ボタンで追加
- 苦手な食材: 同上
- [+] タップ → カテゴリ別チェックリストモーダル（主食/主菜/副菜）
- 苦手な食材は献立から除外、好きな食材は優先的に採用

### 既存セクション

- プロフィール（変更なし）
- アプリ設定（変更なし）

## 5. オンボーディング

初回起動時、プロフィール未作成ならオンボーディング画面に遷移。
完了するまでダッシュボードにアクセスできない。

### フロー

```
起動 → onboardingCompleted === false → オンボーディング画面
                                        ↓
                                    Step 1: 基本情報
                                    名前 / 年齢 / 性別
                                        ↓
                                    Step 2: 体の情報
                                    身長 / 体重 / HbA1c（任意）
                                        ↓
                                    Step 3: 食材の好み（スキップ可）
                                    好き / 苦手な食材
                                        ↓
                                    onboardingCompleted = true
                                    → ダッシュボードへ
```

- Step 1, 2 は必須（献立生成に必要）
- Step 3 はスキップ可能（「あとで設定から登録できます」表示）
- 2回目以降の起動はダッシュボード直行

### ログイン機能との互換性

- `onboardingCompleted` フラグはユーザーデータに持つ
- 将来ログイン実装時はローカルデータをアカウントに紐付けるだけで済む
- AsyncStorageのキー構造は変更しない

## 6. データ構造の変更

### User型の拡張

```typescript
interface User {
  id: string;
  name: string;
  age: number;
  avatar: string;
  createdAt: number;
  healthData: {
    height: number;
    weight: number;
    gender: 'male' | 'female';
    activityLevel: 'light' | 'moderate' | 'high';
  };
  // 新規追加
  foodPreferences: {
    liked: string[];
    disliked: string[];
  };
  onboardingCompleted: boolean;
}
```

### SavedMealPlan型の拡張

```typescript
interface SavedMealPlan {
  id: string;
  userId: string;
  createdAt: number;
  period: number;
  startDate: string;
  meals: { [date: string]: GeneratedMeal[] };
  userProfile: UserHealthProfile;
  name?: string;
  // 新規追加
  glucoseAtGeneration?: number;
}
```

### 新規AsyncStorageキー

- `favorite_meals` — お気に入り料理IDの配列（ユーザーID別）

### 既存キーへの影響

- `users` — User型にフィールド追加（既存データは `foodPreferences: { liked: [], disliked: [] }`, `onboardingCompleted: true` をデフォルトで補完）
- `saved_meal_plans` — 新フィールドはoptionalなので後方互換維持
- その他のキー（`glucose_records`, `weekly_records`, `app_settings`, `currentUserIndex`）は変更なし
